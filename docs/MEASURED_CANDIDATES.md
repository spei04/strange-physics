# Measured candidate production

This first owner-local Linux implementation exposes only
`commit_native_candidates(root, request)`. It executes the existing candidate
producer unchanged under a plan-bound pre-freeze reference/calibration/sensitivity
envelope. Comparison dispatch is explicitly unavailable until the actual-Journal
adapter is implemented. No purchase, selection, handoff, numerical study or parent
task completion is claimed.

The protected admission and trusted installation record are provided by an
independent owner verification step. Actual archive/provenance, lock, interpreter
binary, installed package bytes/origins, dependency bytes and recomputed reference
engine are checked within finite control time. Synthetic installed snapshots are
labeled synthetic and never prove hosted delivery. The historical observation
engine identity is not overwritten by current execution identity. Trusted local
Python and retained owner-controlled ancestors/state are prerequisites; these
checks do not authenticate hostile code already running in this process or detect
whole-state rollback at the same trusted path.

Before full input parsing, one closed-set ticket is permanently consumed. Normal
work cannot use the reserved recovery ticket range. The same durable seed/control
hold is required after restart; missing initialized storage never reseeds. The
controller holds CPU for all finite tickets and bootstrap/tail. Control artifact
capacity uses a single bounded database/PERSIST-journal lifetime envelope, bounded
ticket files and bounded bootstrap files. Work input/output bytes are charged
separately. Deleted or recreated scratch cannot refund prior costs. The metric is
logical new extents, not physical I/O or write amplification.

Each work reservation precedes the actual fixed child. Returned raw result, facts,
measured cost and original-prefix receipt commit atomically; body/attempt/config
and result identities are checked using the existing candidate binder. Genuine
typed rejection remains rejection; killed or malformed execution remains unknown.
Known measurements are retained when storage/time permit; unknown predecessor
holds never disappear. Acknowledgement loss uses a new charged recovery attempt
and returns the exact original bytes/receipt without invoking numerical code.

Extra ledger record/byte room is protected beyond the existing per-unresolved
final-update reserve. The publication profile represents the current publisher's
actual material/Journal/ledger/output work formula and its control floors.
Zero promised publications means this execution is intentionally unpublishable;
it does not invent a manifest. Nonzero promises also restrict ledger growth and
unspent CPU/artifact capacity. No default ticket profile is a study throughput
claim. Capacity denial durably stops new execution while bounded paid recovery
may remain possible; exhaustion may honestly leave stopped/unpublishable work.

Metadata uses a fixed 4 KiB, FULL, PERSIST, no-cache-spill SQLite profile and bounded
growth. One root lock excludes cooperating writers; there is no distributed or
adversarial-owner guarantee. A compact receipt references immutable input/output
files and an original prefix of the append-only ledger, avoiding full ledger
copies per result. All private files remain outside public artifacts.

The initial executable checkpoint is under author validation. Focused tests use
actual installed synthetic builds and real child processes. Purchase/handoff and
other four numerical wrappers remain separately reviewed follow-on work. Full
configured gates and independent review are required before accepting this slice.

The first execution profile requires the historical observation engine fingerprint to
match the independently observed current engine. It preserves the historical value;
cross-epoch execution needs a separate explicit policy and is not supported here.

Exact recovery requires the original logical request identity, not a separately
queried latest ledger head. After binding the retained closure under the root lock,
it reserves fresh accounting work against the authoritative current head. Fresh
execution still requires the caller expected revision and hash to match.

Each remaining recovery ticket also protects an explicit fresh-work CPU/artifact
ceiling, separately from the unresolved control hold and publication escrow. Normal
work cannot borrow that capacity. Recovery requests above their declared ceiling
are denied before consuming a ticket; retained global overruns are not reset.
